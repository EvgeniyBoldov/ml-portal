# Актуальные задачи и архитектурные вопросы

Здесь собраны подтверждённые текущим кодом незавершённые задачи и решения.
Документы в `docs/` описывают действующее поведение; предложения и открытые
вопросы фиксируются только здесь.

## Архитектура памяти

- **Компоновка памяти при необходимости.** Если исходные фрагменты в локальном
  контексте планера или задания начнут мешать работе, отдельно оценить
  компоновку. При её введении заменить текущую точную дедупликацию и сохранить
  scope/provenance. Сейчас память накапливается исходными кусками, без LLM-вызовов
  на её обслуживание.
- **Пользовательские правила для scope проекта.** `FactScope` поддерживает только
  `user` и `tenant`. Если продукту нужно сохранять сообщённые в чате проектные
  правила, определить проверку проекта, provenance, права на запись и lifecycle
  подтверждения. Не сохранять их как tenant facts.

## Проверка legacy-контуров

- Проверить активные DB-managed prompts и операторские overrides на старую форму
  вызова `operation`; обновить сохранённые конфигурации до текущего tool-контракта
  `tool_call`/`tool`, если такие конфигурации ещё используются. В исходных
  промптах memory tools и протоколе агента уже используется `tool`.
- Определить lifecycle оставшегося кода прежней Semantic Memory
  (`MemoryItem`/`MemoryClaim`, shadow extraction/review и direct-publish helpers):
  что ещё является поддерживаемой административной функцией, а что следует
  вывести из эксплуатации. Активная document LongMemory работает через HippoRAG
  и не читает эти записи.
- Решить, нужен ли `MEMORY_SEARCH_BACKEND=legacy`: активный путь по умолчанию
  использует HippoRAG, но переключатель всё ещё включает прежнюю retrieval-ветку
  и её код. При удалении обновить конфигурацию и вызывающие её worker paths.
- Удалить совместимость `team_keys`/`project_keys` в chat-context reducer после
  проверки сохранённых и входящих payloads; текущий контракт использует
  `scope_keys`.

## Runtime limits

- Сверить actor limit fields, admin UI и фактическое enforcement. Текущая
  конфигурация агента применяется к лимиту вызовов инструментов; LLM-call и
  wall-time budgets разрешаются для orchestrator roles, а run ledger ведёт
  общие счётчики и лимиты. Уточнить, какие настраиваемые поля должны реально
  ограничивать агента, и синхронизировать API/UI/runtime.

## Операционная проверка

- Проверить совместное развёртывание и миграции LongMemory API, Celery и HippoRAG
  worker на копии production/shared-схемы; сверить миграции `0191–0193` и
  восстановление незавершённых операций. Проверку рабочей production-базы не
  выполнять в рамках этого аудита.
