# User Guide

Краткий гид для конечного пользователя: что доступно, как это использовать, где границы.

## 1. Что вы можете делать

- Работать в чате с доступными агентами.
- Получать ответы с учетом корпоративной базы знаний (если агент использует RAG/tools).
- Просматривать историю своих диалогов.
- Использовать только те данные и инструменты, которые разрешены вашей ролью и tenant-политикой.

## 2. Базовый сценарий работы

1. Создайте чат или откройте существующий.
2. Задайте вопрос с контекстом задачи.
3. Дождитесь потокового ответа.
4. При необходимости уточните запрос (итеративно).

В блоке хода выполнения видны названия двух последних этапов; предыдущий
приглушён. Зелёная галочка или красный крестик появляются только при явном
сообщении об успехе или ошибке этапа. Через «Подробнее» можно раскрыть историю.
После уточнения или подтверждения ответ также появляется постепенно.
Если соединение прервалось, уже полученный текст остаётся на экране вместе
с сообщением об обрыве.
Частичный ответ помечается «Ответ не завершён», а остановленный пользователем —
«Ответ остановлен».

История загружается целиком, включая диалоги длиннее 100 сообщений. При ошибке
загрузки можно нажать «Повторить». Ответ прокручивается по мере появления текста;
если вы прокрутили историю вверх, кнопка «Новые сообщения» вернёт к концу.

Через «+» можно прикрепить файлы. Кнопка остановки отменяет отправку и во время
их загрузки: сообщение после этого не отправляется, текст и вложения возвращаются
в поле ввода. При переходе в другой чат незавершённая загрузка также отменяется.
Ожидающее подтверждение выполняется только кнопкой «Подтвердить»; Enter активирует
кнопку, находящуюся в фокусе.

Рекомендация: формулируйте цель, формат ожидаемого ответа и ограничения в одном сообщении.

В личном кабинете блок «Проекты для памяти чатов» позволяет выбрать проекты
документного поиска. Выбор объединяется с проектами тенанта. При пустых профилях
используется `company`. Через «Контекст» в чате можно заменить весь набор либо
нажать «Использовать настройки профиля». Явный пустой набор отключает поиск по памяти.
Каждый выбранный проект ищется независимо; ошибка одного проекта не отменяет
результаты остальных.

При загрузке документа в документную коллекцию выберите проект для LongMemory.
По умолчанию выбран `company`; один документ получает один проект.

В разделе «Коллекции» показаны реальные коллекции данных. Глоссарий открывается
отдельной кнопкой над списком. Прежние витрины Project Memory и «Глобальная память»
убраны; добавление документов в LongMemory и просмотр их обработки продолжают
работать через HippoRAG. Ошибка загрузки коллекции или её содержимого отображается
с кнопкой «Повторить», а не как пустой список.

## 3. Как формулировать эффективные запросы

Хороший запрос обычно содержит:

- цель: что нужно получить,
- контекст: где применять ответ,
- ограничения: сроки, формат, запреты,
- критерий качества: что считать “хорошим результатом”.

Пример:

> "Составь план внедрения RAG для отдела поддержки, в формате: этап, риски, метрики. Ограничение: бюджет MVP до N часов разработки."

## 4. Ограничения и почему это нормально

- Не все инструменты доступны всем пользователям.
- Доступ к данным ограничен вашим tenant-ом и политиками.
- Некоторые ответы могут быть неполными, если агент работает в partial-mode.
- Время ответа может зависеть от загрузки и сложности tool calls.

Это не баг, это governance. Да, звучит серьезно, но зато безопасно.

## 5. Что делать, если ответ плохой

1. Уточните задачу (добавьте контекст и критерии).
2. Проверьте контекст задачи и доступные проекты памяти через «Контекст».
3. Переформулируйте вопрос на более конкретный.
4. Если проблема повторяется — отправьте пример диалога администратору/AI инженеру.

## 6. Конфиденциальность и безопасность

- Не отправляйте секреты в свободной форме в чат.
- Используйте только разрешенные источники данных.
- Помните: действия в системе журналируются для безопасности и поддержки.

## 7. Когда обращаться к администратору

Обратитесь к администратору, если:

- нет доступа к нужному агенту/инструменту,
- не видны ожидаемые данные,
- нужна новая интеграция или коллекция,
- требуется изменение прав или роли.

## 8. Что важно помнить

ML Portal — это не «магия в коробке», а управляемый AI-контур. Чем четче постановка задачи, тем полезнее результат.

## Персональные API-токены

В личном кабинете `/gpt/profile`, на вкладке «Учётные данные», создайте API-токен
с названием и сроком действия. Полный токен показывается один раз; список
содержит только публичный префикс и дату последнего использования. Токен действует
с текущими правами владельца, а удаление сразу прекращает его действие.

Передавайте его как `Authorization: Bearer YOUR_TOKEN`. Этот же заголовок
принимает JWT access token. Вызов shadow-агента:

```sh
curl --request POST 'https://your-server/api/v1/agents/shadow/invoke' \
  --header 'Authorization: Bearer YOUR_TOKEN' \
  --header 'Content-Type: application/json' \
  --data '{"agent":"YOUR_SHADOW_AGENT","data":{}}'
```

JWT подтверждает личность, а актуальные статус пользователя, роль и активные
tenant-membership проверяются по базе при каждом запросе. Поэтому отключение
учётной записи или изменение роли начинает действовать сразу; access token не
сохраняет прежние права до истечения срока действия.
При выходе сервер отзывает refresh-сессию; повторное использование уже
обновлённого refresh-токена завершает всю эту сессию.

MCP использует тот же Bearer-заголовок на `POST /api/v1/mcp`, включая initialize.
Старые токены, `X-API-Key` и `/api/v1/api-keys` удалены при переходе на новый
формат; для интеграций необходимо создать новый токен в профиле.

Агенты типа `shadow` вызываются через машинный API и не доступны для выбора
в чате или делегирования планером. Их доступы назначаются через текущий RBAC.
