# Runtime Memory

Полная карта хранения и поиска описана в [Memory](MEMORY.md). Контекст чата — в [Chat Context Memory](CHAT_CONTEXT_MEMORY.md).

`MemoryBuilder` создаёт ограниченный снимок подтверждённых user/tenant facts для одного запуска. `RuntimeTurnState` содержит рабочие результаты, ledger инструментов и ограничения. Журнал исполнения и результаты внешних инструментов не становятся долговременной памятью.

Документные знания читаются через зарегистрированный `memory.search(query, limit)`. Он не обращается к старым claims, glossary или диалоговым facts. Preflight, planner и агенты вызывают один инструмент через общий executor.

Приложение вычисляет scope чата из объединения профилей пользователя и тенанта; явный выбор в чате заменяет набор целиком. При пустых профилях используется `company`, явный пустой выбор в чате отключает документный поиск. Scope — обычный slug без team/project-веток или wildcard.

`execution_context.scope_keys` показывает текущий набор. `memory_search_scope_keys` в ToolContext передаёт его поиску автоматически. Каждый scope имеет отдельный готовый граф HippoRAG и возвращает самостоятельную группу результата. Запросы выполняются параллельно; `limit` применяется к каждой группе. Ошибка или пустая выдача не удаляет группу и не объединяет её с соседней. При нуле scope возвращается ноль групп без поиска.

LongMemory общая для пользователей портала. Native HippoRAG не проверяет ACL исходных документов и не делит память по пользователям или tenant. Scope выбирает тематический индекс из общего каталога, а не ограничивает права доступа. Ordinary RAG и коллекции остаются отдельными контурами с собственными проверками доступа.

Планер накапливает собственные исходные фрагменты по scope на весь запуск; каждое агентское задание накапливает свою память между попытками. Поисковые контексты разных владельцев не передаются автоматически. Продолжение после `needs` наследует память только по явному `continuation_of` в допустимой resolution. Точные дубли убираются кодом; LLM-компоновки и обрезания фрагментов нет. Синтезатор получает подтверждённый материал по правилам [Memory](MEMORY.md#передача-между-runtime-ролями). Нельзя переносить свойства объекта между scope по совпадению темы.

После финального ответа независимый `FactExtractor → FactCompactor → FactReconciler` проверяет первичное evidence и сохраняет только user/tenant facts. Фокус проекта не меняет владельца факта. Sandbox overlays остаются локальными ветке.

В trace записываются реальные tool calls/results и собственные snapshots ролей (`memory_context_used`, `memory_owner`, `memory_owner_id`) перед работой и после каждого поиска. Сырые группы, включая пустые и неуспешные, доступны в результате инструмента. Инспекторы показывают записанный накопленный контекст владельца, без повторного добавления содержимого tool results. Старые журналы не дополняются чтением текущей базы.
