# Компоненты профиля

Профиль объединяет личные настройки, области памяти, редакторов рабочей группы,
учётные данные и сохранённые факты. Эти компоненты используют существующие
API профиля и не определяют самостоятельную модель доступа: серверные
разрешения остаются источником истины.

## Области памяти

В профиле показываются отдельно личные области, области рабочей группы и
сохранённый наследуемый набор. Пользователь редактирует личные области;
области рабочей группы доступны только для чтения и меняются администратором
рабочей группы. Наследуемый набор формируется объединением личного набора и
набора рабочей группы. Если оба пусты, применяется область `company`, если
она присутствует в каталоге. Явный выбор областей в настройках чата заменяет
весь наследуемый набор. Изменения профиля действуют для следующего хода чата,
использующего наследование.

## Управление рабочей группой

Для пользователя с доступом к настройкам рабочей группы показываются списки
редакторов данных и областей памяти группы. Редактирование этих списков
раздельное: сохранение отправляет только соответствующее поле (`data_editor_user_ids`
или `memory_scope_keys`) методом `PUT` на `/profile/tenant-management`.
Фактическая проверка роли администратора рабочей группы выполняется API и не
заменяется доступностью элементов интерфейса.

## Учётные данные и факты

Панель учётных данных различает загрузку, ошибку с повторной попыткой,
пустой список и список записей. Удаление требует
подтверждения. Доступные операции и область учётных данных зависят от режима,
в котором панель встроена.

Панель фактов показывает доступные пользователю факты, включая факты владельца
«Рабочая группа» как общий контекст. Возможность изменения определяется полем
`can_edit` в ответе API. Пояснения описывают контекст использования факта и не заменяют серверную
проверку доступа к данным. Удаление
поддерживает отдельные и массовые операции с подтверждением.

## API-токены и узкие экраны

Токены показаны отдельным блоком: название, префикс, активность, срок и время
последнего использования берутся из API. Счётчик показывает число загруженных
записей, а не отдельный серверный итог. Подтверждение удаления называет токен
и предупреждает о прекращении доступа с ним. Примеры API-вызовов по умолчанию
свёрнуты в раскрываемую инструкцию.

На ширине до 640 px панели фактов и учётных данных используют карточки вместо
таблиц, сохраняя операции и ограничения доступа. Массовые действия фактов
появляются после выбора записей. Вкладки профиля переносятся на узком экране.

## Обновление профиля

При изменении пароля форма показывает связанные с полями ошибки валидации и
ошибки ответа сервера. Закрытие формы очищает введённые секреты. Табы профиля
сохраняют читаемые подписи и переносятся на узкой ширине экрана.

Компоненты не меняют серверный контракт доступа и не гарантируют успешность
операции: API повторно проверяет полномочия и валидирует запрос.
