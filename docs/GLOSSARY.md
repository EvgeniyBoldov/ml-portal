# Корпоративный глоссарий

Глоссарий формирует единый язык компании: для каждого опубликованного термина
есть одно каноническое название, алиасы и определение, подтверждённое текстом
глобального документа. Термин без определения или проверяемого документного
источника не публикуется.

## Источник и публикация

Документ проходит извлечение текста, разбиение на секции и изучение в
`shadow document memory`. Результат `term` содержит `content.definition` и
`evidence_section_ids`. Администратор проверяет кандидат и утверждает его;
`GlossaryTerm` хранит ссылку на этот кандидат. Публичная запись показывает
документ и секции, из которых взято определение.

Публиковать термины можно только из глобальных документов. Локальные документы
tenant и project могут давать знания в Semantic Memory, но не определяют
общекорпоративный словарь. Из чата, TurnPreflight, Fact Extractor и
Fact Compactor определения в глоссарий не записываются. Запрос пользователя
«добавь термин» направляет его к загрузке документа и проверке кандидата.

## Одно определение

Одинаковое каноническое название обозначает одну запись. Повторное
подтверждение того же определения может обновить источник и алиасы. Другое
определение не заменяет опубликованное автоматически: администратор видит
действующее определение и может явно утвердить замену с причиной, которая
сохраняется в журнале решения. Алиасы прежнего смысла при замене сбрасываются.
Проектные правила, ограничения, процедуры и частные значения
хранятся как отдельные утверждения Semantic Memory с собственной применимостью.

При архивировании документа или замене его версии зависимый термин перестаёт
публиковаться до утверждения определения из действующей версии. Деактивация
термина администратором также скрывает его из чтения.

## Чтение

Пользовательская виртуальная коллекция «Глоссарий» показывает опубликованные
термины, определения, алиасы и документы-источники. `memory.search`,
механический поиск перед TurnPreflight и recall используют те же опубликованные
записи и точное сопоставление названия или алиаса. Planner и агенты получают
ограниченный результат с источником через runtime.

Если один алиас совпадает с несколькими терминами, runtime отмечает
неоднозначность для уточнения, не выбирая определение автоматически.

Внутренние термины реализации портала описаны в [Терминах разработки](DEVELOPER_TERMS.md).
